# Design

shared-docs ships data, a few React components, and the shared docs theme:
`assets/theme-tokens.css` (the `--ifm-*` / `--jt-*` tokens) and
`assets/theme.css` (component overrides), which `shared-docs init` copies into
each site. Each site sets its own accent. This file covers the theme's motion
and the repo's own brand.

shared-docs will never have a docs site of its own. The brand only shows up on
the README, the GitHub social preview and the npm page.

## Brand

Generated by [`@rtorcato/brand-kit`](https://github.com/rtorcato/brand-kit) into
`brand/`. The SVGs are the source; the PNGs are rendered from them.

| | |
|---|---|
| Accent | Rose `#fb7185` |
| Tagline | One sibling list for every docs site. |
| Mark | Rose tile, ink lucide `book-open` (`#0A0E16`) |
| Type | Avenir Next (wordmark, tagline), Menlo (install pill) |

**Why rose.** Every sibling in `src/family.ts` already has its own hue. Rose
fills the open slot between swift-common's coral `#ff6f4d` and api-common's
fuchsia `#e879f9`. The options are in
[`accent-options.png`](https://media.torcato.dev/shared-docs/accent-options.png)
(on R2, not in git).

**Why this tagline.** The package description runs to three lines and gets cut
off with "…" on every canvas. The tagline fits on one line of the desktop banner.

### Regenerating

brand-kit doesn't save the flags, so pass them every time or the defaults
(package.json description, accent read from `favicon.svg`) come back:

```sh
npx @rtorcato/brand-kit --update --tagline "One sibling list for every docs site." --accent "#fb7185"
npx @rtorcato/brand-kit doctor --strict --tagline "One sibling list for every docs site." --accent "#fb7185"
```

`--update` never rewrites `favicon.svg`. To change the accent, edit the tile's
`fill` there by hand, then run `npx @rtorcato/brand-kit render`.

### Rules

- Don't add shared-docs to `FAMILY` just to give brand-kit a tagline. That
  would make it show up in every site's sibling grid.
- Keep the accent out of the components. They take colour from the theme
  tokens, and this accent is only for the repo's brand.

## Back to torcato.dev

Every family site links back to [torcato.dev](https://torcato.dev) in two
places. rtorcato signed this off on 2026-10-13 (v3, no icon). The mockup lives
outside this repo.

**C. Navbar breadcrumb, always visible.** The navbar reads
`torcato.dev / js-common`. The `torcato.dev` text link sits before the site
logo, followed by a `/` separator. It shows on every page, desktop and mobile.

- Text only, with no icon. 15px/600 (14px on phones), coloured
  `--jt-muted-strong` (`#aab4c3` dark, `#4b5565` light, both AA on the navbar),
  turning to `--ifm-color-primary` on hover. The hit area is ≥ 44px tall and
  focus rings are visible.
- The separator is the muted colour, weight 300, and not a link.
- In the mobile drawer, `← torcato.dev` is the first row, above Docs.

**B. Footer, above the copyright.** A `← torcato.dev` link (14px, semibold,
footer link colour, ≥ 44px tall) sits on its own line above the copyright.

The Projects dropdown stays as it is (sibling list only). `torcato.dev` doesn't
go in the dropdown.

### How shared-docs ships it

Docusaurus has no config slot before the logo, so the breadcrumb needs a
`theme/Navbar/Logo` override. Ship it from shared-docs as a small theme plugin,
so a site adds one plugin line and swizzles nothing.

- `HOME`: `{ label: 'torcato.dev', href: 'https://torcato.dev' }`, used by the
  breadcrumb, the drawer row and the footer link.
- The footer link goes into `footer.copyright`. Docusaurus renders that field
  as HTML. Keep `copyright()` returning plain text for non-Docusaurus callers,
  and add the link next to it rather than inside it.

### Rules

- Every site uses the shared plugin and exports, not its own copy of the link.
  `doctor` should flag a site that doesn't load the plugin.
- Label it `torcato.dev`, not "Home": "Home" reads as the current site's home.
- No new colour tokens beyond `--jt-muted-strong`. The dashed outline in the mockup
  only marks what's new.
- The plugin wraps the drawer layout, so a site that swizzles
  `Navbar/MobileSidebar/PrimaryMenu` with its own list still gets the
  `← torcato.dev` row. Don't add the row to that list by hand; it would show twice.

## Buy me a coffee

Every family site links to [buymeacoffee.com/rtorcato](https://buymeacoffee.com/rtorcato)
from the footer (#151). rtorcato signed off option A on 2026-10-20. The mockup
lives outside this repo.

**A. Footer line, next to `← torcato.dev`.** The line above the copyright
reads `← torcato.dev · ☕ Buy me a coffee`.

- Lucide `coffee` icon at 16px, then the text, 14px/600 in
  `--ifm-footer-link-color` (`#dfe5ee` on `#0b101a` dark, `#374253` on
  `#f6f8fb` light, both AA). It turns to `--ifm-color-primary` on hover, like
  the `torcato.dev` link next to it.
- The icon gets `aria-hidden="true"` and a 6px gap before the text. It uses
  `currentColor`, so it follows the hover colour.
- The `·` separator is aria-hidden, in the footer link colour at weight 300,
  with 10px on each side. It isn't a link.
- The hit area is at least 44px tall and the focus ring is the same as the
  `torcato.dev` link's.
- It opens in a new tab (`target="_blank" rel="noopener noreferrer"`). The
  accessible name is "Buy me a coffee (opens in new tab)".
- At 320px the line still fits on one row.

### How shared-docs ships it

- `COFFEE`: `{ label: 'Buy me a coffee', href: 'https://buymeacoffee.com/rtorcato' }`,
  next to `HOME` in `src/home.ts`.
- `footerCopyright()` adds the separator and the coffee link inside the
  existing `rt-home-footer` div. Paste the icon as inline SVG with a
  `<!-- lucide coffee, ISC -->` comment, the same as the family marks.
- Style it in `src/docusaurus/home-link.css`, next to the `rt-home-footer`
  rules. Sites change nothing except bumping shared-docs.
- `copyright()` stays plain text, with no link.

### Rules

- Footer only. No navbar button, no Community-column link, and no
  per-site copies (options B and C were turned down).
- No new colour tokens, and no Buy Me a Coffee brand yellow or logo. The
  lucide cup in the footer link colour is the whole treatment.
- The label is "Buy me a coffee", in sentence case.

## Family marks

Every family site gets one mark: a rounded tile tinted with the site's accent,
holding a line glyph in that accent. It's the pattern repo-tooling's wrench
already uses. Only the glyph and the colour change from site to site. rtorcato
signed this off on 2026-10-14. The mockups live outside this repo.

### The tile

| | Tint tile (navbar, hero) | Solid tile (favicon) |
|---|---|---|
| Fill | accent at 13% opacity (10% on light) | accent, opaque |
| Border | 1px, accent at 38% opacity (40% on light) | none |
| Glyph | accent stroke | `#0A0E16` stroke |
| Stroke | 2, in 24-unit glyph space (navbar and hero share the file) | 2.2 |

- Corner radius is 26% of the tile size. The glyph box is 58% of the tile,
  centred.
- Glyphs are [lucide](https://lucide.dev) icons on their 24-unit grid, with
  round caps and joins and no fill. Paste the paths and keep a
  `<!-- lucide <name>, ISC -->` comment in each SVG.
- On dark surfaces the tile uses the site's dark `--ifm-color-primary`, and on
  light surfaces the light one. The favicon always uses the dark accent.
- The tinted tile turns to mush at 16px, so the favicon is always the solid one.

### Where it shows

- **Navbar.** A 26px tile, then the package name as the navbar `title`. It
  replaces every text-only wordmark SVG and letter tile.
- **Hero.** The same tint tile at 72px, centred above the wordmark with a 22px
  gap. In dark mode it gets a soft glow in the accent
  (`drop-shadow(0 0 28px <accent at 45%>)`), and in light mode no glow. Every
  family hero has this slot.
- **Favicon.** The solid tile. brand-kit uses `favicon.svg` as the logo tile in
  the banner and social card, so running `--update` after the swap brings those
  in line too.

### Files in each site

- `static/img/logo.svg` (light tint tile) and `static/img/logo-dark.svg` (dark
  tint tile). Wire them up as the navbar `logo.src` / `logo.srcDark`, drawn at
  26px, and render them in the hero with `ThemedImage`.
- `static/img/favicon.svg` (solid tile). Delete any raster favicon it replaces.
  brand-kit's is a 72 KB embedded PNG today.
- Template, 32-unit canvas (the glyph box is 18.56 = 58%):

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 32 32" role="img" aria-label="repo-tooling">
  <!-- lucide wrench, ISC -->
  <rect x=".5" y=".5" width="31" height="31" rx="8"
        fill="#34d399" fill-opacity=".13" stroke="#34d399" stroke-opacity=".38"/>
  <svg x="6.72" y="6.72" width="18.56" height="18.56" viewBox="0 0 24 24" fill="none"
       stroke="#34d399" stroke-width="2" stroke-linecap="round" stroke-linejoin="round">
    <!-- glyph paths -->
  </svg>
</svg>
```

For the favicon, the `rect` is `width="32" height="32" rx="8" fill="<accent>"`
with no stroke, and the glyph stroke is `#0A0E16` at `2.2`.

### supabase-common hero

It's the plainest hero in the family, so it moves to the db-common /
swift-common layout. Put the code sample in the framed code window and wrap it,
so the horizontal scrollbar goes. Code, buttons and install box share one 620px
column. The hyphen in the wordmark turns grey like its siblings. Add the accent
glow.

### Rules

- One mark per site, from this table. Don't draw a custom glyph or use a filled
  or third-party logo.
- No new colour tokens. The tile uses the site's existing primary.
- Changing a site's accent means changing its `custom.css`, its three SVGs and
  `src/family.ts` together.
- `alt` / `aria-label` is the package name. In the hero the mark is decorative
  next to the wordmark, so use `alt=""`.

## Motion

`assets/theme.css` retunes two transitions that Docusaurus and Infima already
ship, so every site that carries it behaves the same (#141). Keep motion rare:
it only shows that something changed state. Don't add a motion library, swizzle,
or JS for it.

| Where | What moves | Timing |
|---|---|---|
| Copy button on every code block | The check scales 0.6 → 1 and fades in, coloured `--jt-accent`. The copy icon fades out. | 200ms in after 75ms, 120ms out |
| Mobile menu (below 996px) | `.navbar-sidebar` slides with `transform`, and its backdrop fades | 250ms open, 200ms close |

### Rules

- **Easing:** `cubic-bezier(0.2, 0, 0, 1)` for both.
- **Only `transform` and `opacity` animate** (plus Infima's `visibility`
  switch). Never `all`, width, height, top or left.
- **Keep the success icon centred.** Its transform stays
  `translate(-50%, -50%) scale(…)`.
- **Select the hashed CSS-module classes with attribute selectors**, e.g.
  `[class*="copyButtonSuccessIcon"]`.
- **The check needs 3:1** against the button in both themes (WCAG 1.4.11). It
  replaces Docusaurus' hard-coded `#00d600`.
- **Leave `.navbar-sidebar__items` alone.** The single-flat drawer's transform
  lock lives in each site's swizzle files.
- **Reduced motion:** under `prefers-reduced-motion: reduce` there are no
  transitions. The check swaps instantly and the menu appears in place.
- **Out of scope:** page transitions, scroll effects, animated marks. A Lottie
  belongs only on a 404 or empty state, one per screen, and gets its own spec.
